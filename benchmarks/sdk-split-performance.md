# SDK 拆分与上传优化

## 改动

原 1160 行左右的 cldt_client_sdk.cc 拆成 C API、socket、协议、文件、传输流程、工作线程六个实现文件。C API 入口现在为 179 行，各实现文件少于 280 行；公开 API 与 CLDT v2 协议保持兼容。拆分没有在数据通路新增锁、虚调用或线程。

Linux/Android 原生文件上传改用 sendfile，消除 pread/send 的用户态往返和 256 KiB 工作缓冲。每次 syscall 上限 1 MiB；处理 EINTR、短发送、取消、提前 EOF，以及系统不支持时从已发送位置回退。SIGPIPE 使用线程局部屏蔽及恢复，不修改宿主进程的全局信号处理。自定义 I/O 与 Windows/Apple 保持原路径；不宣称这些平台因此获得上传加速。

## 实测

WSL2 / GCC 15.2 / Release，同机 Linux 接口 192.168.80.211，服务端 4 disk worker。每个可执行文件先预热一次，然后轮换前后版本顺序；SHA-256 全部通过。吞吐含进程启动和服务器完成确认；CPU 为客户端与服务器合计。前后版本均为 SDK，完成语义相同，没有通过取消 fsync 改善结果。

| 场景 | 各版本有效轮数 | 上传前/后 MiB/s 中位数 | 吞吐变化 | CPU 前/后秒中位数 |
|---|---:|---:|---:|---:|
| tmpfs，4 路 × 256 MiB | 5 | 3872.75 / 5121.90 | +32.3% | 1.4991 / 0.8829（−41.1%） |
| ext4，4 路 × 128 MiB | 3 | 1041.25 / 1205.03 | +15.7% | 0.9286 / 0.6055（−34.8%） |
| tmpfs，单路 256 MiB | 3 | 1830.86 / 2823.19 | +54.2% | 0.6403 / 0.2838（−55.7%） |

这些是短时本机数据，有明显波动，不能外推到跨机网络、持续负载或手机。单路某轮新版只有 1373.77 MiB/s，低于旧版同轮 1939.01；不承诺每次请求都会更快。

第一组串行“上传后下载”出现下载 9082.97→7644.95 MiB/s。为排除前一阶段影响，补相同本地种子的隔离下载测试，4 路 × 256 MiB、各五轮，中位数 7633.88→7571.83 MiB/s（−0.8%），CPU 0.5473→0.5468 秒。两版下载实现不变，当前数据未证明稳定下载退步或提升。

原始数据：

- `sdk-sendfile-tmpfs.json`：五轮并发上传/下载及预热。
- `sdk-sendfile-ext4.json`：三轮 ext4 上传及预热。
- `sdk-sendfile-single.json`：三轮单路上传及预热。
- `sdk-split-download.json`：五轮隔离下载及预热。

复现工具为 `scripts/compare_sdk.py`。另可将本版 `CLDT_SDK_ENABLE_SENDFILE=OFF` 构建为回退对照。

## 验证与剩余范围

- Linux 完整构建、7 项 CTest、原客户端传输回归通过。
- SDK 快路径开/关均通过上传、stat、下载、非对齐续传、range 尾部保留、空文件、鉴权拒绝、对端断连退出码及自定义内存 I/O。
- Windows MSVC Release、中文路径往返 SHA-256 及内存回调互通通过；Android NDK arm64 API 24 编译通过。
- Android 真机和 iOS/Xcode 仍未验证；Windows 原生上传零拷贝、可取消 DNS/connect、持久化策略和持续压力下的尾延迟仍有后续优化空间。
